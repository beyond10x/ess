## Binding decisions proposed

1. Implementation-owned stored generation is unobserved in an outcome-only history. Before treating generation as a proven executable transfer, establish that its full constrained domain is nonempty. A validated witness may prove existence but is not authority for that value or its optional presence. Recorded creation identity remains authority only for its explicitly addressed identity slot.
2. Run the existing executor's selection, effect ordering and actual readers through a private history context. Do not perform a command-wide dependency audit or use the recorded outcome to select branches. Public native execution and `Generated::{Counter,Given,Recorded}` retain their contracts.
3. Represent unknown values separately from `Node`, path by path, with known existence, absence, null and container shape where justified. Never use a sentinel value or make a missing concrete-map entry stand for unknown to a semantic reader.
4. Preserve predicate Kleene semantics and actual early returns. Refuse only where an actual necessary decision is unresolved. Copying an unknown value is a transfer, not automatically a decision requiring refusal.
5. Execute cross-row reads and set effects against shared history state. Merge interacting partitions instead of banning those commands. An initial single partition for any history that may access another row is sound and simpler than a dependency-component optimizer.
6. Search must distinguish a proven dead branch from an unresolved branch. Without a known valid explanation, an unresolved possible explanation prevents a definite Violation. A fully determined valid explanation may still establish Linearizable under the existing candidate-input approximation.
7. Do not add a history format, recorded-input authority, public response injection, callback oracle or expectation-derived value. Existing independent limitations remain named; this work must not claim every history feature complete.

These decisions refine the prior `value-expressions.md`, `concurrent-history-conformance.md`, and `observed-subject-history.md` contracts: native implementations own generation, history replay uses recorded identity, and unknown facts cannot select a default outcome. They do not change native generation to a symbolic operation.

## Private execution state and representation

Introduce an internal execution context selected by the public concrete wrappers or the private history entrypoint. Keep one control-flow implementation of `responding`, `select`, `take`, existence/refusal precedence and effect application. Do not clone the whole executor into a history interpreter. The context supplies semantic row reads, expression values, writes, validation and final result conversion.

An internal `Value` has known concrete values or abstract values. The abstract representation contains:

- Explicit `Absent` versus present known `Node` versus a value with unobserved content; optional values can carry unknown presence. JSON null and absent retain the existing reader's distinct transfer behavior, even though `defined` treats both as absent.
- Known objects whose members independently contain known or unknown values; known lists/maps retain known membership/cardinality and per-element values. A wholly generated collection has unknown cardinality unless the admitted type proves it. Unknown union discriminator remains unknown; known discriminator preserves known arm shape.
- After nonempty-domain proof, a required generated scalar has known presence and unknown content. A required generated struct can preserve required member presence recursively; optional members have unknown presence unless constraints prove a single possibility. Type/newtype constraints are retained as guarantees about admissible values, not proof that such values exist and not instantiated as a sample. A generation that cannot establish feasibility does not produce a proven successor.
- Stable provenance for each fresh generated location: operation identity, selected branch, exact entity/row, expression path and generation occurrence. Copies keep origin identity. Do not derive it from arbitrary search visit order. Unknown origins and shape participate in state equality; fresh generation and copying are distinct.
- Existing exact `Node` row keys and known lifecycle state. `ess-history/1` text identity admission stays unchanged; never reinterpret a wire string as numeric identity.

Use a private `HistoryStore` with rows containing this representation, or a concrete row skeleton plus authoritative abstract field overlay behind a single facade. The latter is acceptable only if **every** semantic read uses the facade: a skeleton with an omitted unknown field is not a valid public Store and must never be exposed as one or passed to existing concrete bind/validation helpers unchanged. Prefer the explicit private store/value types to make bypasses visible in Rust types. A private history result need not materialize a public Step containing fake event Nodes; it carries actual selected outcome, abstract next store, and existing replay facts.

The ordinary concrete context delegates to current functions and converts to the unchanged public Step/Store. History uses private entrypoint and result types. Work must hold both immutable pre-command read authority and staged next state in its chosen context. Failure, unknown decision and rejected candidate discard all staged state. Each nondeterministic branch owns its own copy. Indeterminate-operation “never happened” preserves the old state. Deletion removes the actual row and its provenance; recreating it establishes fresh provenance. No mutation is inferred from comparing before/after Node bytes.

## Predicate seam: shared evaluation, explicit unknown presence

`subject::Held::selects` already combines the stored predicate with the additional input predicate using `Truth::and`; `Predicate::evaluate` already implements All/Any/Not, comparisons, membership, text/fold operators and quantified predicates. Supply abstract facts there; do not use `fact_paths` as a refusal oracle.

Proposed additive primitive API: `FactSource::observed_presence(path) -> Option<bool>` defaults to `Some(self.present(path))`. `Predicate::Defined` maps None to Unknown. Retain `present(bool)` for source compatibility. Existing concrete sources keep identical behavior. The abstract facts implementation returns Some(true) for required present unknown values, Some(false) for known absent/null and None for unknown optional presence. `fact/observe` returns no scalar for unknown content. Known container counts and leaves remain available. Unknown collection cardinality returns None, never zero. Keep exact numeric and declared Timestamp/type ordering from TypedFacts.

Forward the new presence observation through `WithNow`, quantified `Element` binder rewriting, row/input selection, caller namespace/shadowing, and set-filter wrappers. Any wrapper reached by abstract facts must forward `observe`, cardinality and type metadata with the same namespace mapping, not reconstruct them in a way that exposes a skeleton or drops uncertainty. Concrete-only InputFacts/TypedFacts need no public semantic change; if used as wrappers rather than rebuilt concrete leaves, forward explicitly. Audit all FactSource implementations to establish the boundary.

This adds a defaulted Rust trait method and one shared predicate semantic capability; it does not change source vocabulary, serialization, or generated Go/TS runner behavior. The history checker is native Rust; all explorer histories already call it. Concrete predicate parity tests in Rust/Go/TS must remain unchanged. Add Rust tests covering unknown presence through every relevant wrapper and a nested bound-variable case. A private exhaustive predicate visitor is the alternative, but duplicating Timestamp ordering, quantified scoping, text count, and diagnostics is riskier than this small shared extension.

No abstract facts read itself raises an error: a value read can yield Unknown, and a later false conjunct or true disjunct can resolve the predicate. Only the completed decision at the existing reader seam may refuse. This also keeps `Predicate::outcome` cause handling consistent with the main evaluator. Never treat an unknown first guard as false and select fallback.

The minimum abstraction is not a theorem prover. It must preserve obvious known facts from shape/presence and declared type guarantees, exact known values, and copy identity where needed for validity. If implementation adds symbolic comparison simplification or interval proofs, normalize private predicate leaves and delegate concrete semantics to the shared evaluator; do not introduce a second independent scalar-ordering implementation. A complex unproved algebraic implication may remain unresolved, but blanket refusal of an entire field/command/collection is not permitted. This precision boundary must be explicit in the adopted design and tested; it cannot excuse the concrete false-conjunct/sibling/early-return cases below.

### Generated-domain feasibility: existence without value authority

Use a private three-way feasibility result: `Inhabited(proof)`, `Empty(proof)`, or `Unresolved(reason)`. This is separate from the abstract value and its origin. The source's structural inhabitation check (`ess-domain/src/system.rs:621`) ignores newtype/struct constraints, and predicate admission checks well-formedness, not joint satisfiability. Therefore type admission alone cannot construct Inhabited.

- Reuse the existing typed witness generator and complete typed-value validator to attempt a witness satisfying the **whole** generated value, including nested/newtype constraints and joint struct predicates. One fully validated candidate is sufficient proof of nonemptiness. A field-by-field collection of witnesses is insufficient when a parent constraint relates those fields.
- The witness is private feasibility evidence only. Discard its scalar/member choices when constructing the abstract value; never insert them into HistoryStore, emit them as observed payload, make them a subject identity, evaluate a history guard with them, or use them to resolve optional presence. A satisfiable Timestamp witness before a cutoff must still leave both measured early/late guards unresolved.
- Bounded witness failure means Unresolved, not Empty. A sound exact contradiction (for example an empty intersection of exact numeric bounds, or an exhaustively checked finite domain) can certify Empty. No general solver is required, but any Empty result must carry the actual proof class, not just a timeout or no generated sample.
- Required generation with Unresolved feasibility yields an unresolved alternative before any commit. Required generation with proved Empty yields no executable successor; preserve the existing search distinction between impossible and unresolved alternatives. Neither can contribute a proven complete ordering. This rule applies equally to required stored, event and declared-error payload generation wherever that surface admits generation, even if history/1 omits the payload. The history result adapter must not skip these checks merely because it carries no concrete events/errors.
- Optional of a proved empty inner domain remains inhabited by absence, and absence is then the only legal result: its presence is known false. Optional of an inhabited inner domain admits both absence and present content, so preserve unknown presence. If inner feasibility is unresolved but absence is legal, the Optional domain is still inhabited; record that only the absent alternative is established and that present feasibility remains unresolved. Do not manufacture a proven present branch. A later presence-dependent decision remains unresolved unless independent constraints settle it; choosing absence as a witness is not authority for the actual generated Optional.
- Required structs must pass joint feasibility, not just member inhabitation. Collections/unions obey the same rule: an allowed empty collection or one feasible union arm proves domain existence but does not fix actual cardinality or discriminator. Parent constraints may remove that empty/arm witness and must be validated too.
- Cache feasibility by resolved type/complete applicable constraints, separately from origin-specific abstract state. Cache proof status, not one alleged observed generated value. Settle field-specific constraints/presence policy at the actual target surface rather than reusing an incompatible proof.

Entity post-state invariants remain a separate actual decision after staged writes. A single field's inhabited type does not prove every combined post-state invariant. Those invariant decisions continue using abstract facts and may be known true, false or unresolved.

Required new red-capable fixtures: a required constrained Integer with `value > 0` and `value < 0` must never yield a proven completed creation; a satisfiable constrained required field must retain inert-generation checkability; an Optional of the contradictory inner type must remain checkable as absent and must not enable a present branch; and a struct with individually inhabited fields but a contradictory joint predicate must not pass. Repeat required-generation checks on an event payload and a generated declared-error payload if admitted. Add a satisfiable domain for which bounded witness search cannot establish feasibility to prove that search failure is Model-undetermined rather than a fabricated Empty proof. These are prescribed future executed regressions, not claimed results of this design revision.

## Cross-row state and search correctness

The module's current P-compositionality explanation (`linearize.rs:19`) assumes no step reads another row. Related reads and set effects break that assumption even with no generated data. Do not attach the partition fix only to generated commands.

Use an exhaustive conservative **dependency classifier for grouping only**, examining every possible outcome of commands present in the history, including related guards, value sources nested in structs/error/event payloads, `instances`, and `affects`. If any may cross a row, put all command operations into a single internal partition. This overapproximation costs search effort but does not refuse behavior. Keep existing subject partitions and retry-component grouping when commands are row-local. A later optimization may compute interacting entity components; it is not necessary for correctness.

The internal partition identifier must be separate from a real subject identity. `subjects()` currently also inserts partition names as subjects; that must not create a fictitious row for a global group. `judge` must resolve actual subjects to their group while keeping each operation's exact subject key for addressing/reporting, but must replace the existing subject-key restriction on read-your-writes coverage for an interacting group. Group all actual rows observed/created under the appropriate entity; do not identify an entity/row merely by the group's label. Existing identity-only view-format limitations are not silently broadened.

For an interacting shared partition, a read-your-writes candidate state must cover **every operation in that partition from the reading client which completed with Returned before the read was invoked**, irrespective of the operation's subject key. Retain the actual client, completion and real-time conditions; remove only the `(own.subject_key == subject || own.subject_key.is_empty())` restriction for these groups. This conservative session barrier is necessary because a call addressed to A can alter B through affects/set effects. It does not require unacknowledged calls or another client's calls merely by client identity; those remain governed by the existing temporal/reachability rules. Row-local groups can retain their existing local check. A more precise per-explanation affected-row analysis is a later optimization, not a reason to retain the unsound address-only filter.

Keep this barrier in reach/judge processing as well as the command search: grouping alone supplies shared state but does not make an earlier prefix satisfy the client's acknowledged writes. Under uncertain reachability, a state before the mandatory acknowledged write is never a positive explanation; the existing unresolved-alternative rule still prevents a false definite violation when a qualifying complete path remains unresolved.

Required actual regression must use admitted source, not `affects.moves`: the current domain explicitly rejects lifecycle transitions inside affects (`command/set_effects.rs:225`), admits only field sets there, and rejects combining instance with instances (`:136`). History view judgment currently observes lifecycle membership, not arbitrary affected fields. Therefore the reviewer-suggested direct A-affects-B lifecycle move is not an admitted fixture and must not be reported as executed evidence.

Use the supported composition instead: create distinct A and B rows; client C completes a command with nonempty subject key A whose `when_related` predicate requires B to exist in Active, whose subject updates A, and whose affects updates a normal B field. Include the required related-absent branch. This command cannot acknowledge its accepting outcome before B exists. Then C queries the lifecycle view and wrongly omits B. Under the old subject-key filter, a prefix before B's creation can explain that absent row; under the shared-partition barrier, any qualifying prefix includes C's acknowledged command and thus B's prerequisite creation. The stale omission must fail. This retains an actual A-addressed cross-row mutation without inventing a lifecycle effect inside affects. Domain `related_guard.rs:23` explicitly permits a related guard beside an addressed subject; `set_effects.rs:258` permits affects beside an existing updates/moves subject. Compile the whole composed fixture before treating this source inspection as admission evidence.

Add the healthy view containing B, another-client read with an allowed older prefix, and a no-subject set command control. A no-subject case alone is insufficient: current code already exempts empty subject keys. If the composed fixture reveals a separate existing blocker, retain that diagnostic and isolate a focused direct judge test for the mandatory acknowledged-operation barrier; do not claim the end-to-end regression green or the capability complete until an admitted executable history exercises it. The barrier is explicitly adopted for all interacting groups, including future row effects, without expanding current source admission.

Set selection and related lookups now see rows created by other history operations in the same search state, including indeterminate creations on their applied branch. Their reads use pre-state; commits update actual affected rows. Whole-history real-time ordering, request origin/replay tracking and duplicate-origin rejection remain intact. A set command with no subject still belongs to the interacting global state.

Positive related-history tests must use admitted candidate inputs that address known rows. ## Search uncertainty and view reads

Replace the single undifferentiated error result at `step` with an internal result containing proven next states and an optional unresolved alternative with a diagnostic witness. An unknown earlier guard blocks its fallback in that alternative; it does not produce either guard branch as a proven step. Returned outcome filtering applies only to proven steps. Keep unrecoverable source/admission errors separately from new generated-data uncertainty.

Search result precedence:

- A complete proven valid ordering establishes the command-history Linearizable result under the existing candidate-input abstraction.
- Exhaustion of all alternatives with no unresolved possibility establishes Violation.
- Exhaustion with an unresolved generated-data alternative and no proven explanation yields `CheckRefusal::Model` / check.model-undetermined / CLI2, with operation and reader path.
- Exhausted budget remains Unknown / CLI3, rather than pretending to have exhausted alternatives. Do not overwrite a known proof with a diagnostic from an unexplored branch.

This rule avoids both immediate global refusal because one candidate is unknown and false violation from dropping unknown candidates. Unresolved markers must survive memoization keyed by full abstract Held plus done-set; they are not ordinary dead nodes. Include provenance in equivalent-state and liveness caches.

View reachability requires additional care. `reach` currently finds every prefix on complete valid paths and `judge` uses those prefixes. A proven command ordering alone does not justify a read violation if another unresolved ordering could explain that read. Keep incomplete reachability explicit: a read explained by proven reachable states can pass at the existing per-subject consistency level; a purported read violation depending on excluding unresolved states must become a model refusal, not a violation. Direct contradictions independent of stored generated data, such as a duplicate row, retain their current definite meaning. Lifecycle-only view admission can stay as today; this task does not claim new support for field-dependent view filters currently listed as not judged. Preserve that separate limitation visibly.

## Bounded generated-domain feasibility

The history-only feasibility query has one ephemeral context: completed Inhabited/Empty
proofs for one immutable IR, a separate active dependency set, depth32, 16,384 shared proof
work units, at most64 structural witness attempts and at most256 finite combinations.
An active hit, insufficient depth/work, unavailable facts or Unknown invariant is Unresolved;
none proves Empty or definite optional absence. Unresolved is never cached as a completed
type proof. A later query with adequate resources can therefore recover.

Concrete validation retains its existing String-error wrapper. The private proof entry
distinguishes Invalid from Unresolved and applies false-dominant conjunction to constraints
and members: a proved invalid member/invariant excludes a candidate despite another Unknown,
while an unresolved candidate prevents exhaustive emptiness. One completely validated
candidate proves existence even when other finite candidates remain unresolved. Such a
candidate is discarded and never becomes stored content or observed history authority.

The bounded witness entry tries structural absent/empty bases and productive recursive union
alternatives, with the actual union content key, before falling back to complete finite
enumeration. It shares work accounting with child feasibility, concrete validation, exact
bound extraction and absence queries. Node/key copies, declaration traversal, Cartesian
products and predicate work are charged before expensive construction/evaluation; the existing
fact projector is guarded by a bounded preflight of its actual representation/declarations.
This budget limits proof search, not the admitted source language or native concrete execution.
It is not a wall-clock timeout or a declaration that every inhabited constrained domain can
be established by bounded structural/finite search.
