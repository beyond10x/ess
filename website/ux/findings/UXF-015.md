# UXF-015: tens of key presses to a sidebar link

The keyboard runs of the anchor cards all complete (4 of 4), but they cost far more actions than
the pointer runs of the same tasks. R-02's numbers (`rounds/R-02/round.json`, key
`screen_only.actions` of each scenario):

| task | viewport | pointer | keyboard | expectation | `round.json` scenario of the keyboard run |
| --- | --- | --- | --- | --- | --- |
| first-conformance-run | desktop-1280 | 2 | 23 | 3 | `first-conformance-run/desktop-1280/keyboard` |
| first-conformance-run | mobile-390 | 4 | 130 | 3 | `first-conformance-run/mobile-390/keyboard` |
| install-linux-x86_64 | desktop-1280 | 2 | 21 | 4 | `install-linux-x86_64/desktop-1280/keyboard` |
| install-linux-x86_64 | mobile-390 | 4 | 128 | 4 | `install-linux-x86_64/mobile-390/keyboard` |

R-01 measured 26 and 24 on the phone with the screen-only user R-02 replaced: that user read a
state's controls before the page had rendered (`21e8c21e03`). The phone counts are 5 times R-01's;
the desktop counts did not move. How much of the rise is the site and how much the corrected tool
is not separated: the R-01 tool is unfit as a base (`rounds/R-02/decision.md`, `R-02-baseline`).

From the top of a doc page, Tab passes the logo, the project switcher, seven navbar items and the
theme toggle (the shot) before the sidebar, then every open sidebar entry above the target. On a
phone the menu holds the whole sidebar tree, so Tab walks it entry by entry. No shortcut jumps to
the sidebar or to a search field (the site has none, UXF-001).

## Severity

S3 in R-01. Raised to S2 in R-02 on the heuristic reviewer's recommendation
(`rounds/R-02/review-heuristics.md`, "New findings"): a keyboard user on a phone needs 32 times
the pointer's actions for the same task (heuristic 9, keyboard and pointer parity, fail).

One line: a skip link to the sidebar and to the page body, and a keyboard shortcut to search (with
UXF-001's search), remove most of the presses.
