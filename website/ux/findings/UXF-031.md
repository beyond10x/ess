# UXF-031: the route to a guide on a phone goes through a closed category

This record takes over from UXF-013 the route of `page-a-view` at mobile-390, and only that route.
UXF-013's cause for the other phone routes was the theme's first menu panel, owned by the shared
theme, and R-06 fixed two of them with an in-page link (`first-conformance-run`, `limitations`).
This route's cause is different and the site's: the guides sit behind a closed sidebar category and
the docs index's first screen links to none, so the reader expands Guides, then Write a
specification, then Views before the heading.

A link from the first screen of `/ess/docs`, or the "Where to go next" table
(`website/docs/index.md`, below the first screen) moved above the code block, to the guides' index
would take the route to about 4 actions. Caution carried from R-05: the link must be what a reader
of this site wants, not the card's route.

UXF-013 stays open for the theme's panel and closes on its metric when the theme owner changes it;
the asset of this record is the test UXF-013 listed for `page-a-view`, which fails now.

Affected: 1 of 22 task runs (`page-a-view/mobile-390`); the same shape applies to any guide task
on a phone. Cost M.

One line: link the guides' index from the docs index's first screen so that `page-a-view` at
mobile-390 takes 5 actions or fewer, without raising the docs introduction's reading load.
