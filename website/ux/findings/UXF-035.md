# UXF-035: tool defects of the report stage

Five defects of one kind: `round.json` holds the fact and `report.md` does not print it, so a
reader of the report cannot check a claim the round makes.

- T1: the Runs table prints wall, workers and counts but not `timing.load`, which every run record
  holds; a budget judged at a load of 60 or less cannot be checked from the report.
- T2: no ratchet summary (improved, worse beyond tolerance, worse inside tolerance) and no list of
  the worse-inside-tolerance values; the baseline column is the post-update baseline, so it equals
  the round for every improvement.
- T4: `round.json` holds the engine's commit and not the measured site's (its build commit or
  lock), so a change of the site between engine and record cannot be tied to a state. Same shape as
  R-05's T37.
- T5: the worst-moment caption promises a magenta outline of the first axe nodes, and the shot is
  the top of the page with none in view.
- T7: `budgetLine` in `core/reporter.ts` judges only at the end of a run and only to the log; the
  Runs table has no judged or not judged column, so the report cannot say which runs the 120 s
  budget applies to (the slow lane has none).

Affected: every round report. Cost M.

One line: print the load column, the ratchet summary with its worse-inside-tolerance values, the
site's identity, a scrolled shot of the first node and the budget's judgement per run.
