# UXF-026: layout shift depends on host load

`layout_shift.load` is read once per L2 test, after hydration, under the first theme
(`core/reporter.ts`, `specs/l2-layout.spec.ts`). It is a timing value: the same page at the same
commit read 0.0253 in `slow-l2-4` and 0.0000423 in `rerun-shift`, at different host loads.
`round.json` keeps 0 for that page (values are rounded to 4 places), and the per-viewport sums of
the dark theme rose from R-02 to R-03 (mobile-390 0.028 to 0.039, desktop-1280 0.013 to 0.015)
while no layout changed.

Two consequences: a rerun can replace a worse value until it is low (T27, repaired in R-04 by
keeping both values and comparing the worse), and the worse of two loads is still a value of the
host, not of the page.

Affected: 278 of 556 page configurations carry the value; 31 of them are above 0 in R-03. Cost S.

One line: read the shift on three loads and take the median, or write a value under the tolerance
(0.01) as 0, with the rule named in the baseline's `about`; name the host's load in the round.
