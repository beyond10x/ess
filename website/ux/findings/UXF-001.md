# UXF-001: the site has no search, on any page

Search is an always-visible element of the adapter (`website/ux/adapter.ts`, `alwaysVisible`) at
both gating viewports. No page of the built site renders a search control: 138 of the 139 pages,
548 of the 548 measured configurations (2 viewports x 2 themes); the 139th page,
`/ess/docs/reference/ess-ui`, was not measured (UXF-014).

Examples: `/ess/`, `/ess/docs`, `/ess/docs/start/install`.

A reader who knows a term (`ess/31`, a diagnostic code, a command) has to browse to it: see the
action counts of `ess-31-release` and `diagnostic-type-009` (UXF-010).

## R-02: one finding, one asset

R-01 counted this absence once per page configuration (548 times), which kept gate 2 red on
every page and hid any other gate-2 failure behind it (review of R-01, T3). The site configures no
search plugin, no search theme and no Algolia key (`website/docusaurus.config.ts`), so search is
not an always-visible element of this adapter any more. The absence is this one finding, held by
one test: "L2 site search" reads the built HTML of the 9 template pages and fails while none
renders a search control (a local search bar, a DocSearch button, a search input or landmark).
It goes green when a search plugin is configured; `specs/l1-adapter.spec.ts` shows the check
finding both a built search control and its absence.
