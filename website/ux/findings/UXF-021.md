# UXF-021: gate 5 lost three rules on an unchanged site

R-01 `gates.gate5_accessibility.by_rule` held 5 rules, 2,733 nodes on 104 pages:
`nested-interactive` 2 nodes, `scrollable-region-focusable` 1, `color-contrast` 22 nodes on 2
pages, `label-content-name-mismatch` 6 on 2 pages, `link-in-text-block`. R-02 holds 3 rules,
2,732 nodes on 105 pages: `color-contrast` 4 nodes on 1 page (`/ess/releases/archive`, the `h1`),
`label-content-name-mismatch` 4 on 1 page (`/ess/`), `link-in-text-block` 2,724 on 103 pages. No
`nested-interactive`, no `scrollable-region-focusable`, 18 fewer `color-contrast` nodes.

The site did not change between the rounds; `core/contract.ts` did: R-02 runs axe with
`setLegacyMode(true)`. The report reviewer infers that mode as the cause and did not prove it.

UXF-007 and UXF-008 are open and no longer visible in the numbers, and the R-02 baseline
(`baseline.json`) took the smaller set as an improvement. A round that restores the rules will read
as worse against it: that rise is the repaired measurement and needs its own decision.

Affected: gate 5 on 2 of 139 pages (`/ess/docs/visualise`, `/ess/releases/archive`); the baseline
of all 556 page configurations. Cost M.

One line: find the cause on the two pages UXF-007 and UXF-008 name, and hold gate 5 to every rule
with an L1 test on a doctored page.

## R-03: cause proven, measurement repaired

The cause is legacy mode, and the frame is why. A probe in the scratch directory ran axe on
`/ess/docs/visualise` at both gating viewports, light theme, in both modes and after two waits (the
gate's hydration wait, and network idle plus 3 s). The wait changed nothing. Legacy mode reported
only `link-in-text-block` (3 nodes at desktop-1280, 2 at mobile-390). The default mode reported
those and `nested-interactive` (1, `iframe #dm-canvas`), `color-contrast` (8, buttons inside the
frame), `label-content-name-mismatch` (1, `iframe #appbar > .corner > .repo`), and at mobile-390
`scrollable-region-focusable` (1, `iframe .dm-bottom`). Every lost node sits inside the page's one
`iframe`: legacy mode checks the top document and never enters a frame.

`core/contract.ts` `runAxe` now runs the default mode on a page that holds a frame and legacy mode
on one that holds none (the default mode costs 92 to 112 s on the frameless ess-ui reference page,
R-02). In the built site only `/ess/docs/visualise` holds an `iframe`. Its L2 test took 2.7 s per
viewport with the repair. No rule is dropped.

The asset: an L1 test on a page whose frame holds a control nested in a control, a scrolling
region with nothing focusable and faint text. The R-02 engine reported none of the three rules on
it; the repaired engine reports all three.

Revised in the same round: under load the default mode reported nothing for the frame of the
asset in 2 of 6 runs, because `@axe-core/playwright` drops a frame whose run fails without an
error. `runAxe` now runs legacy mode in the top document and `axe.run` in the document of each
child frame, and merges the results by rule; an error in a frame fails the test. The asset passed
10 of 10 runs under load 90 to 115, and the visualise page still reports `nested-interactive`
and, at mobile-390, `scrollable-region-focusable`.
