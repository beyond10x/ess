## Need

The Rust target of `ess generate synthesize` emits a struct that declares `shorthand:`, and its decoder accepts both spellings: the
object, and the value of the shorthand field alone. A document format whose list entry is "a bare name or a map" (a bare name standing
for an object with a second member left at its default) needs it. Gap 4 of a consumer's request of 2026-11-25.

## Reported case

From a consumer, 2026-11-25. Measured on a 0.99.1 build (0.99.0 plus three synthesis fixes and one UI check fix, none in the
generators), 2026-11-25 03:23 CET, on a copy of the neutral specification of
`story:a-synthesized-rust-crate-carries-typed-decoders-and-encoders-without-a-server-takes-a-package-name-and-leaves-out-its-workspace-table`
with one added struct (`shorthand: requirement`, fields `requirement: String` and `mode: Optional<Mode>`):

```
$ ess generate synthesize --path spec4 --target rust --layout crate --out out4/crate
rust target cannot emit this workspace
types.shop.catalog.Dep.shorthand: `shop.catalog.Dep` declares `shorthand: requirement`, and this target decodes the struct from its object only, not from the field's value alone
exit 1
```

The refusal is `crates/generate/ess-synth/src/failure.rs:369-398` (`shorthand`), called for every target at `crates/generate/ess-synth/src/lib.rs:491` and again for Rust at
`crates/generate/ess-synth/src/rust/mod.rs:196`. It refuses the Rust and Go servers and the web app alike; only the command-line
target keeps its output.

## Findings covered

- Gap 4 of one consumer's request of 2026-11-25.

## Fit review

1. **Need.** A struct written in a short form is a value the specification admits (`ess/27`, beyond10x/ess#594); a Rust crate that
   refuses to generate for it cannot carry the specification.
2. **Class.** A feature: the refusal is by design (the short-form decoder is "owed rather than silently missing", `failure.rs:371-374`).
3. **Expressible today.** No: the target refuses the whole workspace.
4. **Fit.** The short-form decoder belongs to the typed decoder of
   `story:a-synthesized-rust-crate-carries-typed-decoders-and-encoders-without-a-server-takes-a-package-name-and-leaves-out-its-workspace-table`
   (gap 1) and to the served wire module alike, because both are the Rust wire module: one change, both consumers. No format step: the
   key exists since `ess/27`.
5. **Second adopter.** Any served Rust model with a shorthand struct is refused today by the same line.
6. **Cost.** The Rust refusal is removed for structs the decoder handles; Go and web keep it (TD-D7). Generated bytes of a model
   with no shorthand do not change. Release train: next minor.
7. **Existing stories.** None covers it. `story:a-shorthand-struct-binary64-location-resolves` borders (implemented): it is about a Binary64 location
   in a shorthand struct in the published schema, not the Rust decoder.

## Decisions

- TD-D7, scope of the target change. A: the Rust target only; Go and web keep their refusal by name. B: Rust and Go together. C: all
  three refusing targets. Recommended A (the consumer's need is Rust).
- TD-D8, the encoder of a shorthand struct. A: always the object (one canonical spelling; the decoder reads both). B: the short form
  when only the shorthand field holds a value. Recommended A.

## Acceptance

- both_spellings_decode: for a struct with `shorthand: requirement`, the typed decoder reads `"name"` and `{requirement: "name"}` to the
  same value, and a value holding another required field beside the shorthand is refused at declaration time as `ess/27` already says.
- the_refusal_is_gone_for_rust: the specification of the Reported case generates for `--target rust` in both layouts and builds with
  warnings denied; Go and web still name the struct in their refusal (TD-D7 A).
- a_served_model_decodes_the_short_form: a request body written in the short form is admitted by the generated server.
