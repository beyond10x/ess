## Outcome

- `rust-toolchain.toml` at the repository root pins rustc `1.98.1`, with `rustfmt`, `clippy` and
  the `wasm32-unknown-unknown` target.
- Every `dtolnay/rust-toolchain` step that builds this repository reads the version from that
  file, through a `pin` step placed just before it. This covers `ci.yml`, `release.yml`,
  `package.yml`, `pages.yml` and `release-record.yml`. No workflow names a rustc version or
  `stable` any more.
- The `msrv` job still reads `rust-version` from `Cargo.toml` and runs `cargo +<rust-version>.0`.
- The new test `crates/edge/ess-xtask/tests/toolchain_pin.rs` holds all of this and names its
  three exceptions.
- No format version changes. No generated bytes change.

## Why (context only)

- CI's gate runs 1.98.1, written 9 times across `ci.yml` and `release.yml`.
- The release archives (`package.yml`), `pages.yml`, two `release.yml` jobs and
  `release-record.yml` install an unpinned `stable`.
- A local build uses whatever the host's default is (1.99.1 on the development host on
  2026-11-21). So local Clippy is not CI's Clippy, and a release is compiled by a rustc the gate
  never ran.

Decisions taken (story `story:the-local-gate-catches-what-ci-catches`):
- O1: pin 1.98.1. A move is one pull request.
- O2: release archives use the pin from the next release on. Published archives are not rebuilt.

## What to change

**The base.** You are forked from a base in which another unit has already changed `ci.yml`: a
first job `diff` and job-level `if:` conditions on the archive builds and test jobs. Line numbers
of `ci.yml` below are from `origin/main` (release 0.97.1) and will not match your base. Find each
step by its job and by the `uses: dtolnay/rust-toolchain@4360b52568e2003a75bf9bc1d59f33a8e3fc893c # stable`
line. Do not touch any `if:` line, the `diff` job or the `gate` job.

1. **New file `rust-toolchain.toml`** at the repository root. Exactly this content, with no
   comments:
   ```toml
   [toolchain]
   channel = "1.98.1"
   components = ["rustfmt", "clippy"]
   targets = ["wasm32-unknown-unknown"]
   profile = "minimal"
   ```
   Why these lists: the workflows install `rustfmt` and `clippy` (`checks`, `hotfix-checks`) and
   `clippy` (`test`). Nine install steps add `wasm32-unknown-unknown`: `checks`, `build-tests`,
   `build-feature-off` and `test` in `ci.yml`; `hotfix-checks`, `hotfix-tests` and `wasm` in
   `release.yml`; and `pages.yml`. The local gate needs all three (`task fmt-check`,
   `task clippy`, the wasm builds of tests). The workflow steps keep their own `components:` and
   `targets:` inputs, so CI does not depend on how rustup treats the file's lists.
2. **The `pin` step.** It is the same text everywhere. Insert it directly before each
   `dtolnay/rust-toolchain` step listed in step 3, at the same 6-space step indent:
   ```yaml
         - name: Read the pinned rustc
           id: pin
           shell: bash
           run: |
             toolchain=$(sed -n 's/^channel = "\([0-9][0-9]*\.[0-9][0-9]*\.[0-9][0-9]*\)"$/\1/p' rust-toolchain.toml)
             if [ -z "$toolchain" ] || [ "$(printf '%s\n' "$toolchain" | wc -l)" -ne 1 ]; then
               echo "::error::rust-toolchain.toml does not pin exactly one rustc: '$toolchain'" >&2
               exit 1
             fi
             echo "toolchain=$toolchain" >> "$GITHUB_OUTPUT"

   ```
   If the `dtolnay` step it precedes has an `if:`, the `pin` step gets the same `if:` line, placed
   after `id: pin` (this applies only to `package.yml` `candidate`). Every job below checks out
   the repository before its toolchain step, so the file is there.
3. **Each `dtolnay/rust-toolchain` step**, after the change. Keep every other key and comment in

## Tests first

All in `crates/edge/ess-xtask/tests/toolchain_pin.rs`. Each reads a few small files and runs in
well under a second, except the `bash` cases, which take under a second each. Red before steps
1-3 because `rust-toolchain.toml` does not exist and the workflows write `1.98.1`.

1. `the_toolchain_file_pins_one_exact_rustc`:
   - `rust-toolchain.toml` has a `[toolchain]` line;
   - exactly one `channel = "X.Y.Z"` line, where X, Y and Z are ASCII digit runs (so `stable` and
     `1.98` fail);
   - a `components` line containing `"rustfmt"` and `"clippy"`;
   - a `targets` line containing `"wasm32-unknown-unknown"`.

   Red: the file is missing.
2. `every_workflow_reads_the_pinned_rustc`. For every `*.yml` under `.github/workflows/`, every
   job, and every step whose `uses` starts with `dtolnay/rust-toolchain@`:
   - **(a) An exception job.** If `(file, job)` matches `EXCEPTIONS`, skip it, except
     `ci.yml`/`msrv`: assert its `with.toolchain` is exactly
     `${{ steps.msrv.outputs.toolchain }}`.
   - **(b) Every other step:**
     - `with.toolchain` is exactly `${{ steps.pin.outputs.toolchain }}`;
     - an earlier step of the same job has `id: pin` and a `run` that contains
       `rust-toolchain.toml`;
     - that `pin` step's `if` equals the install step's `if`. Both may be absent.

   Also collect the `(file, job)` pairs that matched an exception and had a `dtolnay` step.
   Assert the set is exactly `{("b10x-docs-bundle.yml", "bundle"), ("ci.yml", "msrv"),
   ("planning.yml", "validate")}`.
   This way, a removed exception also fails.

   Red: every install step writes `1.98.1` or nothing.
3. `every_pin_step_is_the_same_script`: every step with `id: pin` in every workflow has the same
   `run` text as the one in `ci.yml` job `checks`, and `shell: bash`. Red: there are no `pin`
   steps.
4. `the_pin_step_reads_the_file_and_refuses_anything_else`. Take the `run` text of the `pin` step
   in `ci.yml` job `checks`. For each case below:
   - make a directory `Path::new(env!("CARGO_TARGET_TMPDIR")).join(format!("toolchain-pin-{}-{index}", std::process::id()))`,
     calling `fs::create_dir_all` on it first;
   - write `rust-toolchain.toml` there with the case's content;
   - run `bash -c <run>` with `current_dir` that directory and `GITHUB_OUTPUT` set to a file in
     it;
   - assert the exit status and the written `toolchain=` line;
   - remove the directory at the end.

   Cases:

   | `rust-toolchain.toml` | expected |
   |---|---|
   | `[toolchain]\nchannel = "1.98.1"\n` | success, `toolchain=1.98.1` |
   | `[toolchain]\nchannel = "stable"\n` | failure, nothing written |
   | `[toolchain]\nchannel = "1.98"\n` | failure |
   | `[toolchain]\n` | failure |
   | `[toolchain]\nchannel = "1.98.1"\nchannel = "1.99.0"\n` | failure |

   Also run it once in the workspace root (the real file) and assert
   `toolchain=<pinned_channel()>`. Red: there is no `pin` step to read.
5. `no_workflow_names_a_rustc_version`. A text scan of each workflow file. Outside the exception
   files `planning.yml` and `b10x-docs-bundle.yml`, no line matches any of these:
   - a `toolchain:` key whose value is not `${{ steps.pin.outputs.toolchain }}` or
     `${{ steps.msrv.outputs.toolchain }}`;
   - `RUSTUP_TOOLCHAIN` with a value other than `${{ steps.msrv.outputs.toolchain }}`;
   - `cargo +` followed by anything other than `${{ steps.msrv.outputs.toolchain }}`;
   - `rustup default` or `rustup toolchain install`.

   The `rust-toolchain:` input key under `.github/actions/` is not scanned. Red:
   `toolchain: 1.98.1`.
6. `the_consumer_profile_measures_the_pinned_rustc`: read
   `crates/edge/ess-xtask/src/consumer_coverage/mod.rs` as text. Assert it contains
   `const MEASURED_TOOLCHAIN: &str = "<pinned_channel()>";` (line 176 at `origin/main` holds
   `"1.98.1"`). Red only because the file is missing. Afterwards it keeps a pin move from leaving
   the consumer profile behind.

   ```rust
   /// The Taskfile selects no rustc of its own; `rust-toolchain.toml` does.

   ```
