## Outcome

A command with a retained result (`replays:`) is answered by the generated Rust and Go servers with
the `response` member their own OpenAPI document requires, for the replaying outcome and for the
outcome it replays, and the generated Rust server for such a command compiles.

## Problem

Found while implementing beyond10x/ess#423/#424 (2026-10-04); pre-existing, not part of them.
Still so on 0.92.0.

Minimal reproduction (`format: ess/7`): command `Seed {document: String}` with a declared
`response` (`revision_id: Uuid`, `stamp: Timestamp`, ...), outcome `seeded` creating a `Record`
and emitting `Seeded`, outcome `replayed` with `external: ...` and `replays: seeded`; one component
accepting `Seed`.

```
$ ess generate synthesize --target rust --path retained.yaml --out rust-out   # exit 0
$ ess generate synthesize --target go   --path retained.yaml --out go-out     # exit 0
```

- Both served OpenAPI documents (`retained-service.openapi.json`) list `response` as required in
  the `seeded` and the `replayed` answer (`ess-gen/src/openapi.rs`, `carries_result`:
  `retains_result || answers_with_response`).
- Rust types declare `SeedOutcome::Seeded { response, seeded }` and `SeedOutcome::Replayed
  { response }` (`ess-synth/src/rust/items.rs`, `carries_response`, which includes
  `retains_result`).
- The Rust server matches them as `SeedOutcome::Seeded { seeded }` and `SeedOutcome::Replayed`
  (`retained-server/src/wire.rs`) and `SeedOutcome::Replayed` (`retained_service.rs`): a pattern
  missing a field and a unit pattern for a struct variant, which `rustc` refuses. The patterns are
  chosen by `answers_with_response` only (`ess-synth/src/rust/wire.rs`, `outcome_encoder`;
  `ess-synth/src/rust/http.rs`, the answer function), not by `carries_response`.
- The Go server's `answerRetainedCoreSeed` writes `outcome` and `published` and no `response` for
  either branch (`ess-synth/src/go/http.rs`, `direct_response`, again `answers_with_response`
  only), so its answer breaks the schema it serves.

## Acceptance

- `a_retained_result_is_answered_with_its_response`: for the reproduction, the generated Rust
  server crate compiles, and both servers answer the `replayed` and the `seeded` branch with a
  body holding `response`, encoded by the command's response encoder, which validates against the
  served OpenAPI document.
- The Rust outcome encoder and served answer bind `response` exactly where the variant carries it
  (`carries_response`), for every outcome of a command with `replays:`.
- A command without `replays:` and without `returns: true` keeps its generated bytes in both
  targets.
