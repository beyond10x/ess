## Outcome

- A new repository check, `crates/edge/ess-xtask/tests/target_tmpdir.rs`, fails when a test
  function puts a file or directory directly into `CARGO_TARGET_TMPDIR` before anything in that
  function creates that directory. It names the file, the function and the call.
- It finds 4 such calls in the tree today. All 4 are fixed here: 3 in `external_request_binding.rs`
  (ess-synth) and 1 in `mutation_identical_answer.rs` (ess-conformance).
- The check parses source with `syn` and builds nothing. It runs in seconds.
- No format version changes. No generated bytes change.

## Why (one paragraph, for context only)

A CI test shard extracts the test binaries into a fresh `target/`, which has no `target/tmp`. In a
local tree, `cargo test` creates it, and earlier runs leave it behind. So
`tempfile::tempdir_in(env!("CARGO_TARGET_TMPDIR"))` passes locally and fails on CI with `NotFound`.
That happened in commit `fc1ffeb859` and cost a second full CI run. The fix in that commit was one
line, `fs::create_dir_all(env!("CARGO_TARGET_TMPDIR")).unwrap();`, placed before the call. This
check stops the next case before it is pushed.

## The rule (implement exactly this, nothing more)

**Files.** Run `git ls-files --cached --others --exclude-standard -z -- '*.rs'` in the workspace
root and keep every path that contains `/tests/` and whose text contains `CARGO_TARGET_TMPDIR`.
Today that is 356 files. Parse each one with `syn::parse_file`. A file that does not parse is a
finding: `<path>: could not be parsed: <error>`. There is no allow-list.

**Functions.** Look at every `syn::ItemFn`, every `syn::ImplItemFn`, and every `syn::TraitItemFn`
that has a default body, at any depth. Nested `fn` items count as functions of their own. Walk
each function body in source order with a `syn::visit::Visit` implementation (the walker). The
walker skips nested items: override `visit_item` with an empty body. Closures belong to the
function they are written in.

**The root.** An expression is *the root* when, after removing `&` (`Expr::Reference`) and
parentheses (`Expr::Paren`), it is one of these:
- `env!("CARGO_TARGET_TMPDIR")`: an `Expr::Macro` whose path's last segment is `env` and whose
  `mac.tokens.to_string()` is exactly `"\"CARGO_TARGET_TMPDIR\""`;
- a call whose function path ends in the two segments `Path`, `new` or `PathBuf`, `from`, with
  one argument that is the root (this covers `Path::new(env!(..))`, `std::path::Path::new(..)`
  and `PathBuf::from(..)`);
- a method call `.to_path_buf()`, `.to_owned()` or `.into()` with no arguments, whose receiver is
  the root;
- a single-segment path naming an identifier in the function's root set.

**A direct child.** An expression is *a direct child* when, after removing `&` and parentheses, it
is one of these:
- a method call `.join(x)` with exactly one argument, whose receiver is the root;
- `.to_path_buf()` or `.to_owned()` on a direct child;
- a single-segment path naming an identifier in the child set.

**`let` bindings.** In `visit_local`, call `syn::visit::visit_local(self, local)` first, then
classify the binding. Classify only when the pattern is `Pat::Ident` (no subpattern), or a
`Pat::Type` that wraps a `Pat::Ident`, and the `let` has an initializer:
- initializer is the root: insert the name into the root set and remove it from the child set;
- initializer is a direct child: insert the name into the child set and remove it from the root
  set;
- anything else: remove the name from both sets. A name bound again to something else is no
  longer tracked.

**Created.** Each function has one flag, `created`, which starts `false`. In `visit_expr_call`,
first call `syn::visit::visit_expr_call`. Then, if the function path's last segment is
`create_dir_all` and any argument *mentions* the directory, set `created = true`. An expression
mentions the directory when it contains, at any depth, an `env!("CARGO_TARGET_TMPDIR")` macro or
a single-segment path naming an identifier in the root set or the child set. Use a small inner
`Visit` with `visit_expr_macro` and `visit_expr_path`. Once `created` is set, it stays set for
the rest of that function.

**Findings.** A finding is recorded only while `created` is `false`:

| shape | where it is matched | condition |
|---|---|---|
| `tempfile::tempdir_in(R)`, `tempfile::tempfile_in(R)`, `TempDir::new_in(R)`, `NamedTempFile::new_in(R)` | `visit_expr_call`, function path's last segment is `tempdir_in`, `tempfile_in` or `new_in` | first argument is the root |
| `Builder::new().prefix(..).tempdir_in(R)`, `.tempfile_in(R)`, `Command::current_dir(R)` | `visit_expr_method_call` (call `syn::visit::visit_expr_method_call` first), method `tempdir_in`, `tempfile_in` or `current_dir` | first argument is the root |
| `std::fs::create_dir(C)`, `fs::create_dir(C)` | `visit_expr_call`, last segment `create_dir` (exactly, not `create_dir_all`) | first argument is a direct child |
| `std::fs::write(C, ..)`, `fs::write(C, ..)` | `visit_expr_call`, last segment `write` and the segment before it is `fs` | first argument is a direct child |
| `File::create(C)`, `std::fs::File::create(C)` | `visit_expr_call`, last segment `create` and the segment before it is `File` | first argument is a direct child |
| `fs::copy(from, C)` | `visit_expr_call`, last segment `copy` and the segment before it is `fs` | second argument is a direct child |

Everything else passes, and it is meant to:
- `create_dir_all` of the root or of any path under it. This includes
  `fs::create_dir_all(root.join("model"))`, because `create_dir_all` creates the parents too.
- Handing the root or a path under it to a command (`.env("CARGO_TARGET_DIR", ..)`, `.arg(..)`,
  `--target-dir`), to `GOCACHE`, or to a helper function.
- Reading, `exists()`, `remove_dir_all` and `read_dir`, which do not fail on a missing parent in
  this sense.
- Writing below a subdirectory, as in `fs::write(root.join("x"))` where `root` is itself a direct
  child. The parent there is that test's own subdirectory, so a missing parent fails locally too
  and is not this class of defect.

**Message.** One line per finding:
`<path>: fn <function>: <call>(<argument>) needs CARGO_TARGET_TMPDIR to exist and nothing before it in the function creates it; add std::fs::create_dir_all(env!("CARGO_TARGET_TMPDIR")) before it`.
- `<call>` is the matched last segment or method name.
- `<argument>` is `quote::ToTokens::to_token_stream(arg).to_string()`.
- Line numbers are not printed: `proc-macro2` is built without `span-locations`, and this unit
  must not change that.

**Real shapes in the tree** (lines at `origin/main`, release 0.97.1):

4. Passes, `create_dir_all` of a path under a direct child: `crates/edge/ess-cli/tests/binary64_adversary.rs:9-11`.
5. Passes, a subdirectory handed to cargo: `crates/generate/schema-contract/tests/normalization_rust.rs:187`
   (`.env("CARGO_TARGET_DIR", Path::new(env!("CARGO_TARGET_TMPDIR")).join("normalization-rust-target"))`).
