     ```yaml
     format: ess-composition/6
     conformances:
       - local: {service: relay, type: relay.session.Opened}
         conforms_to: {service: wire, type: wire.session.Opened}
         writer: true
     ```

  2. The question: can the local type send a value the imported type's reader refuses? If it cannot, the difference is admitted; if it can, it stays `type_conformance_drift`. The dual of the reader's.
  3. The presence table (25 cells, below) with the line "a field with no `presence:` writes either absent spelling and, as the published schema reads it, reads only a missing key; equal forms always conform".
  4. The narrowing table (below), and the sentences: a required local value is admitted where the imported one is `Optional`, at any position; the plain entry's tolerance (a local `Optional` against a required value) does not apply to a writer. Enum variant attributes, wire names, map keys, lists and every rule not in the table are compared as without `writer`. The same rules apply to an `event`, `error` or command `part` end.
  5. Refusals: `writer: true` with `reader: true` on one entry is refused when the document is read, naming both keys; `writer` whatever its value (`null` included) under `/2` to `/5` is `unsupported_format` naming `ess-composition/6`; a role's `implements` comparison never reads it.
  6. **Precondition** (as the reader's): an extra field against an ignoring struct holds only because the imported struct declares `undeclared_fields: ignored` (`ess/24`); the comparison reads that key, the author asserts nothing.
  7. **Departure**: none from an issue; the presence table's `unstated` row follows the published schema (parent Decision 3).
