## Need

The generated React project assumes it is served from `/`. `routes.ts` and `router.tsx` read
`window.location.pathname` from the root, `www/index.html` loads `/assets/main.js` and
`/assets/main.css` absolutely, and `pushState` and `<a href={props.to}>` carry no prefix. An app
published under a subpath (static hosting under a project path) loads no assets and matches no
route. Nothing refuses it. Item 1 of the 2026-11-09 workbench report, on 0.92.0; example
`.engineering/repro/workbench-2026-11-09/examples/ui00`.

## Acceptance

- `ess generate ui --target react` accepts a base path. The generated app loads its assets, matches
  its routes and builds its links and history entries under it.
- Without the option, the generated bytes are unchanged.
- A base path that is not an absolute path is refused
  by name.

## Scope

- inferred: `crates/ui/ess-ui-react/src/emit.rs`, the router and `www/index.html` templates,
  `crates/edge/ess-cli` (`generate ui` flags), the React tests.
