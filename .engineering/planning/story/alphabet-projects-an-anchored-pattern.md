## Outcome

A `String` newtype's `alphabet:` (and its `prefix:`) is asserted by the projected JSON Schema,
OpenAPI and AsyncAPI definition as a `pattern`, beside the `x-ess-alphabet` annotation it carries
today, so `ess generate schema validate` refuses a value outside the alphabet as the generated Rust
decoder already does.

Closes https://github.com/beyond10x/ess/issues/592. This is the second slice of
`story:schema-tools-accept-projection` (arrives with branch `integrate/ess-wave-20261017`, which
lands #590, #591 and #593); it is a story of its own because it moves generated bytes and lands
alone, so its drift is the only drift in its merge.

## Fit review

Tree `a500f9f56` (0.62.0). The first-slice fit review on `integrate/ess-wave-20261017`
(`.engineering/planning/story/schema-tools-accept-projection.md`, tree `2c0378386`) covers all four
issues; this section restates the #592 answers against this tree.

1. **Need.** A newtype `{kind: newtype, of: String, alphabet: "0123456789abcdef"}` projects to
   `{"type": "string", "x-ess-alphabet": "0123456789abcdef"}` (issue #592; the annotation is
   written at `crates/generate/ess-gen/src/types.rs:308-309`). JSON Schema validators ignore `x-`
   keywords, so `ess generate schema validate` accepts a value outside the alphabet. Requester's
   proposed syntax, labelled as theirs: "the projection carries an equivalent `pattern` (e.g.
   `^[0-9a-f]*$`), keeping `x-ess-alphabet` for round-tripping".
2. **Class: defect.** `website/docs/reference/spec-versions.md:133` states the alphabet as a
   constraint on every value of the type, and 0.62.0 made the generated Rust decoder and the Rust
   spec-types crate enforce it (`CHANGELOG.md` 0.62.0, #579 decoder and spec-types halves). The
   projection is the one consumer that silently drops it.
3. **Already expressible?** No. No authored construct puts a `pattern` into the projection, and
   editing the projected file after every generation is the idiom policy 1 of
   `docs/design/generic-language-features.md:468-473` refuses (it takes a checked constraint out
   of ESS's own output).
4. **Fit.** The pattern is derived, never authored: `^<escaped prefix>[<class>]*$`, or
   `^[<class>]*$` without a prefix, the class written as `\uXXXX` escapes so that ECMA-262 reads it
   the same with or without the `u` flag (the reason `types.rs:767` gives for refusing a class
   today). A prefix is inside the alphabet by validation, so the conjunction is one anchored
   pattern. `x-ess-alphabet` stays, so the importer and the realizer keep reading the annotation.
   Targets: the three projections that embed the shared type mapping change bytes for alphabet
   newtypes; Rust, Go and TypeScript realizations, the interpreter, synthesis, `ess verify diff`
   and the entity runtime read no projected schema. The types-only realizer must not report the
   alphabet twice (once from the annotation, once from the pattern).
5. **Second adopter.** Any code alphabet: hex digests, base32 tokens, the DTMF digits of the
   repository's own `crates/verify/ess-conformance/tests/fixtures/keypad.yaml`; a service that
   validates incoming documents against its published projection.
6. **Cost.** No authored key, no source format, no diagnostic code. One `pattern` line in every
   projection of an alphabet newtype: adopters' `--check` reports drift once; the repository's
   committed projections and website data regenerate (`task projection-check`).
7. **Alternatives.** (a) Change nothing: the validator admits what every decoder refuses. (b) A
   `format:` vocabulary keyword: not standard, validators ignore it too. (c) An anchored `pattern`
   beside the annotation (chosen; the requester's design passes question 4 unchanged).

## Decisions

- **Accept as proposed.** BMP alphabets get the pattern; an alphabet with a supplementary character
  keeps today's annotation-only projection and the prefix pattern (no class can be written that
  every dialect reads alike).
- Lands alone in its merge, after `task:land-the-schema-tools-wave-branch`, so the regenerated
  projections are the only drift of that merge.
- Reversible: dropping the pattern restores today's bytes; the annotation never moved.
