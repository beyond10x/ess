## Outcome

Documentation lines the 2026-09 fit review found contradicting shipped behaviour
(`docs/design/review-external-requests-2026-09.md` § 3, "stale lines CO:156, CO:220, GP:139, CL:25";
§ 2, S24) state shipped behaviour. The review cited line numbers at `1bd946d6b`; the lines have
moved since, and this body names where they are now.

## Problem

Checked against main at 0.92.0 (documentation read, nothing to run):

- **CL:25, still stale.** `CHANGELOG.md:2554`, in the `[0.48.0]` section, says
  "`ess-conformance-results/1` (unreleased) is the results document"; the format shipped in 0.48.0
  (`website/docs/reference/formats.md:389`, "Added in 0.48.0").
- **GP:139-140, still present.** `website/docs/guides/specify/guards-and-predicates.md:300-301`:
  "In a state the command does not move from, no branch is selected by the stored fields". From
  `ess/18` a subject predicate may read `state`, and the precedence order selects a held-state
  refusal by the stored fields before `wrong_state` answers (same page, § "Which branch answers",
  step 3), so the sentence no longer holds as written.
- **CO:220, moved.** The sentence now lives in
  `website/docs/guides/specify/selection-effects.md:96-97` ("Every generated code target (Rust, Go,
  Web, Clap) refuses both constructs by name"), while `website/docs/guides/synthesize.md:276` says
  generated Rust keeps a command using `instances:` or `affects:` a whole obligation naming the
  construct. Both describe the same behaviour in different words; the guide should say what
  `synthesize.md` says.
- **CO:156, fixed.** `commands-and-outcomes.md:157-160` now says generated Rust looks the identity up
  through its storage port and Go, Web and Clap refuse (changed in `482bc33c25`, 0.51.0). Nothing to do.
- **`UNFINISHED`.** `crates/generate/ess-gen/src/http.rs:133-140` already names both cases a `501`
  covers (a port's unmet obligation, and a committed effect whose delivery to a binding failed), and
  `openapi.rs:1303` says the same in the contract. The remaining point is the summary line, "the
  command could not be carried through because the realization is unfinished", which is false for
  the committed-delivery case.

## Acceptance

- `CHANGELOG.md` no longer calls `ess-conformance-results/1` unreleased:
  `grep -n 'ess-conformance-results/1. (unreleased)' CHANGELOG.md` prints nothing.
- `guards-and-predicates.md` no longer says that no branch is selected by the stored fields in a
  state the command does not move from; the replacement sentence agrees with step 3 of § "Which
  branch answers" on the same page.
- `selection-effects.md` says for `instances:` and `affects:` what `synthesize.md:276` says: Rust and
  Go keep the command an obligation naming the construct; Web and Clap refuse it by name.
- The first sentence of the `UNFINISHED` doc comment (`ess-gen/src/http.rs`) covers the
  committed-delivery case as well as the unmet obligation, and `UNFINISHED_MEANING`
  (`ess-gen/src/openapi.rs`) agrees with it.
- `cargo xtask docs` and the docs build pass.
