Suggested id: story:set-effect-filters-read-the-identity-and-code-targets-owe-set-effects
Suggested title: A set effect's filter reads the row's identity, and code targets owe set effects instead of refusing them

## Outcome

From `ess/25` the filter of `instances:` and of an `affects:` entry reads the candidate row's
identity, as a row-set selector already does, so an outcome changes the one record its subject
refers to by a stored identity (`affects: [{entity: Call, where: call_id == subject.call_id, moves:
Call.end}]`) or the record an input names. Synthesis witnesses such a pinned filter. The Rust, Go,
Web and Clap targets emit a workspace for every specification with set effects: the command is an
owed behaviour whose contract names the rows it changes. Generated Rust and Go behaviour executes an
`affects:` entry whose filter pins the identity, through the storage port's `get`.

Closes https://github.com/beyond10x/ess/issues/547. Design: `docs/design/set-effect-identity-filters.md`.

## Fit review

The design page answers all seven questions with citations; summary:

1. **Need.** A command changes, in the same outcome, the one record its subject refers to by a
   stored identity, or the record an input names. From the referring side the filter is refused
   (`ESS-COMMAND-003 unobservable_fact`, `ess` 0.59.0 at `3fdd9479e`), and no specification with
   any set effect can be regenerated by a code target (`rust|go|web|clap target cannot emit this
   workspace`). Requester's syntax: `where: <identity> == subject.<field>` or `instance:
   subject.<field>` without `each:`; generation over a filter or over one row by identity.
2. **Class: defect, twice.** (a) `filtered-related-reads.md` says the row-set selector uses the
   set-effect filter's grammar; `check_filter` reads `entity.fields`
   (`ess-domain/src/command/set_effects.rs:1224-1242`) while `candidate_fields` adds the identity
   (`row_set.rs:240-251`), and the same predicate validates as a row-set guard. (b) The workspace
   refusal (`ess-synth/src/set_effects.rs:41-79`, 2026-09-28) contradicts the obligation
   `determined.rs:190-195` plans, the Clap design (`clap/mod.rs:30-32`) and the web bridge
   (`web/mod.rs:23-30`); the implementor's seam takes only the input.
3. **Already expressible?** Only from the other side (call as subject: valid, 6 of 6 scenarios
   interpreted), which needs the adopter to turn its API around; no code target idiom.
4. **Fit.** No new key, no IR shape change, no schema change; the identity is read as the row-set
   selector reads it. Composes with `when_related: {via}` refusals, moves, deletes, `sets:`, the
   subject exception and the zero-row rule. Siblings then differ only by `state`, named as not in
   scope. Every target handles or names it.
5. **Second adopter.** Cancelling a booking releases the seat it holds (`where: seat_id ==
   subject.seat_id, moves: Seat.release`); forgetting a device token idempotently (`deletes: Token`,
   `instances: {where: token_id == input.token_id}`).
6. **Cost.** Rides `ess/25`. One new refusal site (`conflicting_declaration`), one format gate, one
   hint; no new `ValidationCode`, suite version or `ess-diff` version. D4 turns refused workspaces
   into emitted ones; nothing that emitted before changes.
7. **Alternatives.** Change nothing; D4 alone; `via:` in `affects:`; `instance:` without `each:`;
   identity in the filter (chosen).

## Decisions

Decision: **accept, redesigned** (the first spelling as proposed; the second spelling declined;
generation narrowed to the pinned case plus owed-not-refused everywhere).

- D1: from `ess/25` a set effect's filter reads the candidate's identity, bare; `state` stays
  unreadable there. Below `ess/25` it is refused as `unsupported_format_version` naming `ess/25`,
  alone.
- D2: `instance:` without `each:` stays refused (`ESS-COMMAND-004`); its hint names the identity
  filter. `instance:` in `affects:` means create-or-update per element.
- D3: no `via:` in `affects:`.
- D4: Rust, Go, Web and Clap no longer refuse `instances:` or `affects:`; the command is owed, and
  its contract names the rows. The re-key refusal outside Rust stays. This reverses the target
  paragraphs of `set-effects-over-filtered-instances.md`.
- D5: generated Rust and Go execute an `affects:` entry whose filter pins the identity (`<identity>
  == subject.<field> | input.<path>`, alone or as one conjunct of a top-level `all:`) through
  `get`; every other set effect stays owed until generated storage enumerates selectors.
- A pin over the subject's own entity whose operand is the subject's identity is refused
  `conflicting_declaration` (it selects only the excepted subject).
- Reversible: D1 admits a new shape only at `ess/25`; D4 changes generated output only for
  specifications that were refused.
