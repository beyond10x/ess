# d799 (servers): generated servers write `null` for an absent `null_when_absent` member

One of two units for beyond10x/ess#799; the other is
`d799-a-cleared-view-member-is-claimed-and-published-in-its-declared-presence` (suite and
interpreter).

Size: S-M (about 160 changed lines: 40 source, 120 test).
Fixed suite bytes of committed models: none (no suite change). Generated bytes change only for a
model with a `null_when_absent` member in a record a server encodes; none of the committed generated
trees has one (the committed models carrying presence have no view or carry it on an input or a
struct; `served_codec_names` and `go` are not expected to move).
Patch-release candidate: yes by content (no committed byte, no diagnostic code; generated code of
affected models changes to what its schema already requires). It ships with the one pull request
of open issues unless the operator orders a hotfix, which is then cut from the 0.98.0 tag with its
own `release-notes/<version>.md`.

## Need

beyond10x/ess#799, item 2. With `presence: null_when_absent` the published row schema requires the
member and admits `null`, and the generated Rust server leaves it out when it holds nothing: its
encoder is the same text for every `presence:` value. A client validating against the schema, or a
suite claiming `null`, fails against the generated server.

## Reproduction

Reproduced on 0.98.0 (generated text; no generated server was built or run). `--path repro/799-<variant>`,
`ess generate synthesize --target rust --layout crate --out out/rust`: in all four variants
`out/rust/src/server/wire.rs` holds

```rust
    if let Some(held0) = &value.note {
        json::member(out, "note");
        json::push_text(out, &*held0);
    }
```

and nothing for an absent `note`; the `null_when_absent` variant's row schema lists `note` under
`required` with `anyOf [string, null]`.

## Outcome

Where a member is declared `null_when_absent`, both generated servers write the member with `null`
when it holds nothing; every other presence keeps today's text (left out). The change sits in the
shared member encoder, so view rows, event payloads, errors and command responses all follow it.

## Cause (read in the source, not run)

- Rust: `crates/generate/ess-synth/src/rust/wire.rs`, `view_encoder` (442) → `record_encoder` (454)
  → `encode_member` (749-772), which receives only the type: `if let Some(heldN) …`, nothing when
  absent. `event_encoder` (380) and the error and command encoders use the same `record_encoder`;
  the header at 100-116 states no presence handling.
- Go: `crates/generate/ess-synth/src/go/http.rs`, `view_encoder` (857) → `record_encoder` (870) →
  `encode_member` (942): `if src != nil { … }`.

## Acceptance

1. Red today: for the `null_when_absent` variant, the Rust `encode_view_depot_bins_bins` writes
   `"note":null` when `note` is `None`, and the Go view encoder does the same for a nil `Note`.
2. For the other three variants the generated `wire.rs` and Go encoder are byte-identical to 0.98.0
   (apart from the contract digest line).
3. An event field declared `null_when_absent` is written as `null` when absent by both servers (the
   shared encoder).
4. The committed generated trees under `generated/` keep their bytes.

## Scope

- `crates/generate/ess-synth/src/rust/wire.rs`: `record_encoder` passes each field's
  `naming.presence` to `encode_member`; under `NullWhenAbsent` an `else` branch writes the member
  and `null`.
- `crates/generate/ess-synth/src/go/http.rs`: the same in `record_encoder`/`encode_member`.

## Changelog

Under `Fixed`:

- The servers `ess generate synthesize --target rust` and `--target go` write `null` for an absent
  member declared `presence: null_when_absent`, in view rows and every other record, as the
  published schema requires, where they left it out (#799).

## Fit review

1. Need: a generated server must answer what its own published schema requires. No syntax.
2. Class: defect. The row schema (`ess-gen/src/types.rs`, `object_annotated` 839-875) requires the
   member under `null_when_absent`; `website/docs/guides/specify/wire-names.md:157` says the same.
3. Expressible: not applicable.
4. Fit: no surface; generated text for one presence.
5. Second adopter: any API that publishes "known to be empty" as `null`.
6. Cost: generated code of models with `null_when_absent` members.
7. Considered: change nothing; change the schema to "not required" (rejected: contradicts the
   documented policy); write `null` (chosen).

- Decision: accept as proposed.
