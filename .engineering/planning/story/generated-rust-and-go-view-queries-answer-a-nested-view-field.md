## Need

A served view with a nested view field (`story:a-view-field-nests-source-fields-under-a-struct-member`)
must be answered by the generated Rust and Go view queries, or refused by them by name. A view
field with `expr:` is kept an obligation named by its expression
(`website/docs/guides/specify/values-and-views.md`, after the operator table). A nested mapping of
plain source fields needs no evaluator: each member is a copy of one stored field.

## Acceptance

All tests are in `crates/generate/ess-synth/tests/view_nested_field.rs` (new), run with
`cargo test -p ess-synth --locked --test view_nested_field`, on the parent story's reproduction
model (`example.files.FileDetail` with `content` and `metadata: example.files.Meta` nesting `id`
and `name`), served by a `reached_by: network` component.

- `the_rust_query_answers_a_nested_view_field`: `ess generate synthesize --target rust` output
  builds with warnings denied, and its served-HTTP test reads `FileDetail` for a stored file as
  `{"content": …, "metadata": {"id": …, "name": …}}` with the stored values.
- `the_go_query_answers_a_nested_view_field`: the same for `--target go`: the module builds and its
  served-HTTP test reads the same row.
- `a_nested_expr_member_keeps_the_query_owed`: with a member `{expr: …}`, `SynthesisPlan::of`
  gives `SynthesisDisposition::Obligation` for `CapabilityKind::ViewQuery` `example.files.FileDetail`,
  and its reason names that expression, as for a top-level `expr:` field.
- `a_nested_related_member_keeps_the_query_owed`: with a member `{related: …}`, the disposition is
  `Obligation` whose reason names the reference, as for a top-level navigated field.
- `cargo test -p ess-synth --locked --test served_codec_names --test go --test
  generated_view_queries` passes with no pinned byte moved: a model without a nested view field
  keeps its generated bytes.

## Fit review

1. **Need.** A generated server answers the nested row, or refuses it by name. Requester's syntax
   (theirs): "projected as the nested object in the generated schema and OpenAPI".
2. **Class.** Gap, following the parent story.
3. **Already expressible?** No (parent story).
4. **Fit.** Every target handles a construct or refuses it by name
   (`.agents/skills/assessing-external-requests/SKILL.md`, question 4). Plain copies are answered,
   and computed members follow the existing `expr:` obligation.
5. **Second adopter.** The address read of the parent story, served by a generated Go service.
6. **Cost.** Generated code changes only for models that declare the form.
7. **Alternatives.** (a) Keep every nested view field an obligation: honest, but needless for plain
   copies. (b) Answer copies and navigations, keep expressions an obligation: chosen.

## Decisions

accept, redesigned, as the parent story.

- Entity Runtime lowers no view (`docs/design/view-paging.md`, "Projections"), so this story
  changes nothing there and has no acceptance for it.
- A `{related: …}` member is kept owed because a generated query today keeps every navigated read
  owed (`view_query::view`, "a read through the reference …"); it is answered when top-level
  navigated fields are.
