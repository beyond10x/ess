## Acceptance

- Recommended: components that declare the same `cli.binary` are generated into one clap crate, whose
  `tree.rs` defines every group of every such component, and `main.rs` dispatches exactly the groups
  `tree.rs` defines. A test over a toy model with two components sharing one binary runs each
  group's command through the generated binary.
- A group name or command path declared by two components that share a binary is refused at
  validate, with a named code that names both components.
- The alternative, if the merge is declined in the fit review: validate refuses a `binary:` shared by
  two components, with a named code. The generated output is never a tree that defines fewer groups
  than `main.rs` dispatches.
- A model with one component per binary keeps its generated bytes.

## Problem

Reported 2026-10-29 on ESS 0.77.0 by a downstream session, through the orchestrator. Not yet
reproduced in this repository.

- Setup: three components, each `reached_by: command_line` with the same `cli: {binary: <name>}`
  and one distinct group each.
- `ess validate` accepts the model with 0 refusals.
- `ess generate synthesize --target clap` writes `crates/<name>-cli/src/tree.rs` with only the last
  component's group, while `main.rs` dispatches all three groups. Two groups cannot be reached from
  the binary.

Minimal repro to write: the model of `crates/generate/ess-synth/tests/clap.rs` (binary `desk`) plus a
second component that declares the same `binary:` and its own group.
