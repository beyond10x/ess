## Decisions taken by the coordinator

- The test-scratch story is split by crate into three units so no two units edit one file
  (scoper's count: 33 files with no cleanup, 58 that clean up without a drop guard, 18 already
  guarded). Each unit writes its own drop guard; no shared crate or new dev-dependency.
- d1 refuses at validation, because every generated HTTP path comes from
  `ess_gen::http::routes`; one refusal covers every target.
- d3 moves two directories cached in a process-lifetime static
  (`binding_arrangement_typescript.rs` `package()`, `support_nested_response/foreign.rs`
  `typescript_package()`) from `$TMPDIR` to `CARGO_TARGET_TMPDIR`. A static never drops, so no
  guard can remove them; under the target directory `cargo clean` does. This is the one change to
  `CARGO_TARGET_TMPDIR` usage the story's acceptance otherwise excludes.
- d3's phase 2 runs `cargo check` and clippy over every ess-conformance test target and 6 of the
  110 changed binaries locally (one build slot, 15G); the pull request's CI runs the rest.
